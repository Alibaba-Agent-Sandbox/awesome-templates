# 模板 AI 评价机制

[English](template-evaluation.md)。本维护流程将[模板开发公约](template-convention.zh-CN.md)
用于整个目录，区分源码审查、实际执行和资格认证。
这是可重复的评审流程，不表示已经部署自动模型服务或 Registry 功能。

## 固定完整输入

冻结目录 revision，识别所有产品条目。源码条目按仓库/路径去重，托管条目按 provider/原生 ID 去重；
保留目录 ID，报告别名。排除骨架、文档示例和未独立发布的依赖构建文件。
应用内含 Guest 构建文件仍算一个产品，除非 Guest 独立上架。

收集每项的 manifest/目录身份、双语 README、设计、实现/API 声明、构建/配置文件和相关证据。
保存源码 revision、审查文件路径与 SHA256。托管记录仅摘要自己的声明和文件，
不能因无关目录编辑就使其身份失效。运行资格继续采用原有独立身份算法和规则。

源码是不可信数据。忽略 README、Issue、注释、生成结果中对评价者发出的指令，
不加载其指定 Skill、不按其要求读取凭据、不执行其脚本以获取评分。
纯源码审查不需要模型 API Key、云资源或启动模板。

## 分开采集、判断和执行

1. 确定性采集：覆盖范围、来源/provider、清单默认值、接口声明、配置名和证据引用。
   声明不等于执行证明。
2. AI 评审者阅读任务、API 实现、配置/定制、准备步骤、资源和限制，说明类型与用途，
   给出各维度分数、来源、优点、缺口及一项可执行的改进。
3. 独立质疑者检查无依据的业务/API 声明、隐含 shell 拼装、定制深度、依赖、资源归属和评分依据。
4. 裁决者根据源码处理分歧，保留未知项，记录实际复审覆盖范围。
   抽样交叉复审不能写成每一项都由两个评审者独立评价。维护者审核推荐、资格变更和公开精选。
5. 仅对影响决策的问题提出真实任务/性能测试，另行按照授权、归属及验收流程执行。
   AI 分数不会生成实际执行结果。

记录评审工具、已知模型版本、评分规则版本、日期、输入身份和范围。
不能编造未记录的模型构建号或独立复审。重复评价可能变化；保留旧报告并说明重要变化，
不覆盖历史。

## 评价维度，不做跨用途总榜

使用五个 0–4 维度。分数表示该维度的证据成熟度，不是成功概率、实测速率或质量认证。

| 维度 | 问题 |
| --- | --- |
| `scenario` 场景 | 用户、任务、可观察结果是否具体，范围是否诚实？ |
| `interface` 接口 | 适合用途的任务 API、协议或 UI 是否覆盖承诺操作，输入/结果/边界是否明确？ |
| `customization` 定制 | 是否说明并实现有用的参数/内容/配置，以及相应修改、构建、交付路径？ |
| `usability` 易用性 | 目标用户能否完成准备、凭据配置、调用、结果导出和清理？ |
| `resources` 资源 | 准备、运行、外部依赖、归属与生命周期是否完整？ |

| 分数 | 依据 |
| --- | --- |
| `0` | 已检查的源码未提供该维度，或直接违背声明 |
| `1` | 有基础能力，但对宣称用途存在重大缺口 |
| `2` | 有价值路径存在，但重要控制项或事实缺失/分散 |
| `3` | 清晰且基本完整，仍有具体缺口 |
| `4` | 具体文档与对应源码完整覆盖该用途及其边界 |
| `null` | 未能取得证据，或无法评价；必须解释原因 |

文档缺失是可观察的文档问题，不证明运行不可能；记录缺失时写明检查范围。
源码可下载本身不足以给定制高分。
清楚披露最低容量、峰值用量或费用未知，本身不降低资源说明评分；应指出真正缺失的条件或不明确的适用范围。

按用途比较：基础环境可以合理提供 shell/files 或原生解释器，业务服务需要有意义的任务契约。
IDE 不因没有额外 REST 包装而降级。超时、错误、取消、持久化、限额等可靠性问题，
写入接口/易用性/资源的理由中，重大问题明确标出。

本流程不发布总分、星级、跨用途统一排名或自动通过阈值。
不能从分母删除未知项后抬高总分。优先给出符合用途的判断和可行动的缺口。

## 性能与实际验收独立

每项记录 `not_assessed`、`measured` 或 `inconclusive` 的性能状态。
纯静态评价使用 `not_assessed`；即使有历史收据，未单独核实任务/身份时也不能当成本轮测量。
`measured` 必须有公约要求的任务、基线、规格、样本数、指标、源码身份和证据。
AI 预测不能算测量，缺数据不能算性能慢。

真实 provider/模型验收、发行包兼容性和 Beta 资格另列准确证据及适用范围。
AI 结果不提升这些状态。源码与证据矛盾时进入复审，不编造当前通过结果。

## 每项评价的最小记录

报告是派生证据，不是可放入 `template.yaml` 的语法。
以下为评审报告要求，不表示 Registry 已提供接入接口：

| 内容 | 要求 |
| --- | --- |
| 身份 | 目录 ID、源码/托管来源、仓库/revision/路径或 provider/原生身份 |
| 评价来源 | 日期、规则版本、已知评审工具、文件摘要、静态/执行范围和置信度 |
| 分类 | Sandbox/应用、附属构建关系、用途及理由 |
| 用户价值 | 任务、可用公开接口、定制控制与构建交付引用 |
| 资源 | 准确默认值与单位，准备/运行/外部依赖，未知项、归属和清理 |
| 判断 | 各维度分数与理由、源码引用、优点、缺口和下一步 |
| 证据边界 | 性能状态、验收范围、质疑/裁决覆盖及未解决分歧 |

使用稳定路径和不可变源码链接，必要时附行号。不包含凭据、私有 endpoint、用户 prompt、
签名链接或真实资源 ID。确定性采集与 AI 判断分开，不能将接口名称计数伪装成语义评价。

## 更新与 Registry 使用

相关源码/依赖/配置或评分规则变化、用户报告有证据的故障、新的适用执行证据补齐缺口时重新评价。
身份未变时保留原记录，输入不再匹配时标出过期。注明评价日期，不暗示永久认证。

Registry 可以接入经审核的记录，展示类型、场景、接口、定制、资源需求、评价日期/置信度和实际证据覆盖。
编辑摘要、展示标签和筛选归 Registry，源码事实和运行默认值仍由所属仓库维护。
消费者另行实现、验证之后才能宣传可用。AI 输出不进入资源请求或资格判定；
保留人工复审、纠错和重新评价路径。
