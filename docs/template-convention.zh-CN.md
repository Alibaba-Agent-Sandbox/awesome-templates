# 模板开发公约

[English](template-convention.md)。本公约面向模板作者和评审者，与[可执行清单规范](template-spec.zh-CN.md)、
[项目规范](project-standards.zh-CN.md)和[文档规范](documentation-standards.zh-CN.md)配合使用。
公约补充设计与评审要求，不增加 manifest 字段、CLI 命令、自动资格认证或运行时协议。

## 什么是好的模板

好的模板帮助明确的用户完成有价值的任务，产生可预期的结果，允许用户调整任务所需的内容和参数，
并说明准备、运行和移除它所需的资源。预装软件有基础设施价值，但不能据此宣称业务开箱即用。

作者必须给出一个完整路径：**输入 → 操作 → 可观察的结果 → 导出或继续使用 → 清理**。
写清实际支持范围，以及还需要调用方实现的部分。基准测试的一个切片不能描述成完整上游产品，
供开发者组合的基础能力不能描述成已经完成的业务应用。

## 分别描述交付类型和来源

| 交付类型 | 用户获得什么 | 必须说明 |
| --- | --- | --- |
| Sandbox 模板 | 含工具、文件、运行时或任务服务的实例 | 创建/连接、使用有价值的接口、导出结果和释放实例 |
| 应用模板 | 管理自身 Sandbox 使用的可部署服务 | 业务入口、应用配置与部署、状态、Sandbox 归属、结果访问与移除 |

应用可以同时构建 Sandbox 模板。应写清依赖关系；除非作为独立产品发布，否则不重复计入目录。
如果用户仍需管理并访问实例，Sandbox 内有 HTTP 服务仍属于 Sandbox 模板。
稳定的外部业务 endpoint 是托管应用体验的一部分，不要求每个基础 Sandbox 都提供。

来源是另一维度：源码构建或提供方托管。托管运行时保留所属 provider 和原生身份。
目录现有维护标签、Beta/提供方资格与交付类型、AI 评价分别处理。
不能直接把已有目录中的 `kind` 字段解释成交付类型。

同时说明用途：基础环境/工具链、任务服务、Agent 运行时、开发服务或基准测试。
按用途评审。提供 CDP 的浏览器、解释器、IDE 可以是好的基础能力，不必冒充完整业务流程。

## 提供适合用途的接口

任务或业务服务应让用户提供任务输入，避免要求用户自己拼装安装、shell 引号、进程管理和输出解析。
接口契约应包含：

- 参数类型、必填/默认值、范围、支持的文件和允许的副作用。
- 有意义的结构化结果或可下载产物，以及独立检查成功的方法。
- 校验与执行错误、认证、状态和重试语义。
- 缓冲/流式输出、执行期限、取消行为和保留状态。
- 所有适用的受支持入口使用同一个任务的完整示例。

适用时复用现有 server SDK 的命名命令接口。`abx run <id> <name>` 和
`client.commands.run(...)` 调用已注册的 HTTP 操作；`abx exec` 和
`sb.commands.run(...)` 才是进程执行。判断接口契约，不能看到 `run` 就认定为裸 shell。

| 形态 | 评审结论 |
| --- | --- |
| 接受任意 shell 文本的 `execute(command: str)` | 是进程传输接口，本身不足以构成业务任务 API |
| 文档转换：输入/格式/期限，返回路径/大小/hash，并有明确错误 | 即使底层调用 Pandoc，也可以是有价值的任务接口 |
| Agent 任务：工作区/文件/模型控制，结果/状态/产物访问 | 文档中的控制项已实现时，是可定制的 Agent 接口 |
| IDE 浏览器 UI、CDP 或适合用途的原生协议 | 是有效接口；额外包装 REST 不必然增加价值 |
| 只有版本/健康检查 | 属于诊断，不能证明宣称的任务可用 |

可以为高级用法保留进程执行能力；但宣传为业务开箱即用的能力，不应只有这一条可用路径。
应用客户端应访问文档中的服务入口，无需了解每个 Sandbox 的地址或管理提供方凭据。

## 定制必须有用，而且可以重复交付

只描述真正支持的定制层次：

| 层次 | 作者应展示 |
| --- | --- |
| 任务参数 | 修改输入、输出格式、工作区、预算或任务选项 |
| 配置与内容 | 按用途修改 prompt、模型/endpoint、工具/Skills、策略、流程内容、文件或依赖 |
| 源码扩展 | 指出修改文件、扩展点、约束和兼容边界 |
| 构建与交付 | 使用现有工具构建/启动修改后的 Sandbox 源码，或构建/部署修改后的应用 |

至少给出一个有意义的修改及其结果。说明哪些修改需要重启、重建或重新部署，更新后哪些内容保留。
只改软件版本、只给仓库链接，都不足以构成完整定制指南。特定用途模板不能承诺任意流程或模型。
客户端 HTTP 等待与任务执行期限、本地客户端关闭与远端资源删除，必须分别说明。

用户配置和实际扩展说明放在对应指南、设计或贡献文档中，由模板链接过去。
使用真实配置名。说明每种凭据的用途、来源和注入方式，不泄露值。
正常 CLI 配置应通过现有受支持流程生成、保存默认应用 token；高级自定义 token 和外部客户端另行说明。
应用 token、Sandbox API 凭据、云 AK/STS 与模型 Key 的用途不同。

## 说明完整资源需求

manifest 中的 Sandbox CPU/内存请求不是应用总成本。资源与配置说明应覆盖：

| 类别 | 需要说明的信息 |
| --- | --- |
| 准备资源 | 主机系统/架构、所需构建工具或 Docker、产物/镜像仓库、构建磁盘和部署权限 |
| 运行资源 | Sandbox CPU/内存及单位、磁盘需求、必需的 GPU/权限、端口、生命周期、工作区持久性和并发 |
| 外部服务 | 按用途说明必需/可选的模型账号、PostgreSQL/存储、FC/SAE 等 Serving、网络/VPC/TLS、数据集和许可证 |
| 归属与移除 | 谁准备和付费、部署新建还是借用、保留期/TTL、结果导出、正常删除和失败恢复 |

每项资源标明**必需或可选**、**部署创建或用户提供**、配置/引用来源及清理责任方。
依赖需要事先存在时应直接说明；不能因为存在 binding 就暗示系统会自动创建数据库。

区分配置默认值、已验证最低配置和实测用量。最低配置或峰值未知时写明未知。
不能根据 CPU/内存字段推断磁盘、GPU、地域可用性、货币价格或容量。
内存单位和限制遵循真实清单及提供方契约，不把 MB 静默改成 MiB。
说明资源是每实例、每活跃 Session 乘算，还是独立部署的服务资源。
可以说明计费类别，不给无依据的费用估算。

例如 [agents-api](../agents-api/README.zh-CN.md) 除每个活跃 Session 的 Guest Sandbox，
还需要 Server FC 角色、已有 PostgreSQL、镜像存储和模型访问；根资源字段仅描述 Guest。
[document-tools](../document-tools/README.zh-CN.md) 则提供有边界的本地转换，不需要模型账号。
两者的资源说明应体现这些差异。

## 性能需要测量

API 可以降低接入工作量，但不直接证明计算或延迟减少。
逐次启动进程和常驻服务在启动、内存、并发上各有取舍，应先确定主要耗时阶段。

性能声明需要可复现的任务和基线、准确模板/依赖版本、provider/地域/规格、输入规模、
样本数、冷/热启动区别和并发。按用途记录启动或首个结果延迟、端到端延迟分布、吞吐、
失败及资源占用，说明模型/网络波动和限制。测量过程与脱敏证据留在工程记录；
用户文档可说明由此确认的支持限制，并链接证据。

没有这些测量时标为未测。健康请求成功、AI 意见都不是性能基准。
缺少性能数据是待调查项，不能直接据此断言模板很慢。

## 验收与维护

沿用现有[完成标准](project-standards.zh-CN.md#完成标准)与[验收规范](template-spec.zh-CN.md)。
任务示例检查实际结果；编码任务独立检查文件和测试，不能只看模型响应标记。
保留失败尝试和准确版本范围，不为填充 AI 评价重复运行付费云测试。

新模板和所宣称能力的修改应一起评审任务、接口、定制、资源与生命周期。
已有模板产生明确改进项；本公约不静默改变它们的 schema、隐藏条目或提升资格。
有证据的缺口以独立、适当范围的改动处理，并完成相应回归与用法更新。

## 模板事实、AI 结果与 Registry 展示

| 归属 | 权威内容 |
| --- | --- |
| 模板源码 | 实际执行的 manifest、实现、任务/API/配置、定制和资源事实 |
| 工程证据 | 绑定版本的静态评价、提供方/模型结果、性能测量与清理证据 |
| Registry | 展示分类、翻译/摘要、筛选、推荐语，以及带来源的证据展示 |

Registry 应展示交付类型/来源、场景、可用接口、定制层次、准备/运行/外部依赖，
并说明信息属于作者声明、静态评价还是实际执行结果。
AI 评价是派生数据，与作者声明分开，不能覆盖原生身份、运行资源请求或 Beta 资格。

纯展示与编辑信息通过独立评审的目录或 Registry 展示契约承载，默认不放进执行 YAML。
本公约没有定义新的可用 metadata 字段，也不表示 Registry 已经展示了它们。
后续机器可读接入需要在所属仓库明确消费者、版本、校验和迁移。

全量评价按照 [AI 评价流程](template-evaluation.zh-CN.md)执行，结论用于评审和改进，不构成认证。
