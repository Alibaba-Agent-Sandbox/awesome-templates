# Decision: Accept actual compatible-agent workflows individually

Status: proposed

## Problem
Successful model turns alone cannot qualify CLI/SDK/HTTP examples, report export,
configuration changes or the full template interface. Startup-only empty settings
were also incorrectly described as always requiring a local template copy.

## Decision
Preserve failed documentation attempts and accept Crush only after its native
coding controller and three fresh documented alternatives complete. Explain that
empty startup settings use new exports plus a new public-recipe instance; nonempty
manifest defaults still require explicit source changes. Keep other agents pending.

## API Design
No runtime/manifest/API changes. Shared bilingual guidance distinguishes per-call
model arguments, empty startup settings and nonempty manifest defaults.

## Alternatives considered
Reusing generated files across consumers, changing host exports on a running
process, or promoting a core-model pass would not prove the requested experience.

## Dependencies
Refs https://github.com/Alibaba-Agent-Sandbox/awesome-templates/issues/244,
https://github.com/Alibaba-Agent-Sandbox/blogs/issues/16 and Registry's reviewed
acceptance index. Use actual standalone CLI0.5.7 and client/server0.4.0a6.

## Test Strategy
Real default Docker build and Express deployment; all three named methods;
original source repair, unchanged three tests, independent held-out results and
actual report; literal CLI, complete SDK, HTTP with absent old outputs, downloaded
program execution and three independently downloaded generated reports. Use two
actual configured startup models across separate instances; independent cleanup.

## Acceptance criteria
Scoped evidence and docs checks pass. Each agent needs its own complete workflow
and article before Registry promotion. No other template gains qualification from
this record; the50-template request remains open.
