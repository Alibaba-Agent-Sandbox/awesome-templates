# Decision: Make Qwen Code a generation-2 headless coding template

Status: proposed

## Problem

The legacy Qwen template used a generic Python base, root configuration, an invalid `--max-turns` CLI switch, floating Python/server dependencies, incomplete authentication guidance and a response-marker-only coding test. It could appear locally healthy without proving the CLI modified or tested code.

## Decision

Migrate this template to spec v2 with the Alibaba FC base and non-root generation-2 server. Retain the existing exact CLI pin 0.23.0, confirmed by installing the package and executing its real `--version`/`--help`. Keep compatibility commands `qwen`/`run`, map public `max_turns` to valid `--max-session-turns`, and add real version and non-mutating setup diagnostics. Authenticate explicitly with OpenAI-compatible mode; accept a DashScope key fallback only in the child process. Require explicit `yolo=true` for automatic approval of all tool operations. Clean up the owned Linux process group on success, error and deadline, retaining the session leader until group cleanup and redact environment secrets from success and failure output.

## API Design

`qwen(prompt: str, max_turns: int=100, model: str="", cwd: str="", command_timeout: int=600, yolo: bool=false) -> str` returns buffered CLI JSON text. Adds `qwen_version() -> str` and `qwen_setup_check() -> dict`; the latter reports only installation, version, configuration presence and JSON validity. `run(script="main.py")` remains a Python script compatibility command. No wrapper operation writes settings. Full arguments, ranges, error statuses, authentication, client versus execution timeout, CLI/SDK/HTTP examples and extension workflow are documented in both languages.

## Alternatives considered

- Keep a reply marker as coding evidence: rejected because it proves neither source changes nor independently verified behavior.
- Write authentication settings from diagnostics: rejected because a read-only health/setup call must preserve user files and permissions.
- Upgrade CLI at the same time: rejected; the existing exact pin is available and supports the required contract.

## Dependencies

Refs https://github.com/Alibaba-Agent-Sandbox/awesome-templates/issues/26. The pinned server source is the repository-approved SDK commit; a task-built compatible wheel may override it during deployment. CLI is `@qwen-code/qwen-code@0.23.0`. Express build/deploy still requires an available Docker daemon. Catalog/shared acceptance-runner integration belongs to the coordinating change.

## Test Strategy

Static spec check, typed HTTP command smoke and behavior regressions for non-mutating diagnostics, authentication guard, exact CLI options, explicit tool approvals, redaction and owned descendant cleanup. Protocol regressions reject forced/missing-key skips in required mode, marker-only results, altered original tests, failed independent tests and failed held-out calculations. Real coding uses existing calculator source, new REPORT.md/exact acceptance.txt artifacts, target file downloads and independent target shell test processes.

## Acceptance criteria

- Spec v2 conformance and regression checks pass.
- Real CLI version is 0.23.0, and required CLI/model modes cannot skip acceptance.
- Real coding modifies existing source, preserves original tests, creates/retrieves artifacts and passes independent tests.
- L1 image build, L2 Express and provider evidence remain mandatory before claiming those levels or publishing an official status.
- Cross-review, required repository checks and PR gates pass before merge.
