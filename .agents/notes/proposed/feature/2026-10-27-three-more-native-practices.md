# Decision: Record three further native business experiences

Status: proposed

## Problem
AppWorld, QM and browser IDE need full method/business/documentation evidence
before any Registry qualification and practical articles.

## Decision
Preserve per-template actual core/docs receipts, all five named methods, independent
artifact execution/native replay, browser editing and exact resource absence.
No runtime changes; original failure attempts remain immutable and separate.

## API Design
No public contract changes. Actual CLI/full SDK/direct HTTP alternatives run on
the same launched application. Registry promotion and blogs are separate owner PRs.

## Alternatives considered
A health response, native exit0, generated prose or unopened IDE login page cannot
establish the business results. Encrypted AppWorld data is not published.

## Dependencies
Refs https://github.com/Alibaba-Agent-Sandbox/awesome-templates/issues/244 and
https://github.com/Alibaba-Agent-Sandbox/blogs/issues/16. Published CLI0.5.7 and
client/server0.4.0a6. Exact local image cleanup fix is already merged in PR267.

## Test Strategy
Method inventory, matching manifest/staged-source/provider identities, actual
expense benchmark replay and generated source execution; actual IDE password login,
edit/save and independent downloaded source execution. Docs/spec/secret/diff checks.

## Acceptance criteria
Current-head CI/review, source evidence merge, individual article, Registry review
and public readback. Broad50-template request remains incomplete.
